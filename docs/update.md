# 更新、备份和迁移

代码和个人资料分别存放。`config.local.json` 指向代码目录外的个人数据库，安装环境位于 `.venv` 和 `.tools`。Git 默认不包含这些个人文件。

更新前先在工作台导出当前维护视图，并用 SQLite 备份接口为整个个人数据库建立一致备份；运行中的数据库不要只复制主文件忽略 WAL。保留本机配置，授权令牌继续交给官方 CLI 管理，不放进备份压缩包或 Git。

更新前用旧目录的 `stop.ps1` 停止本安装工作台，并避免与正在进行的采集整理同时升级。从 GitHub 获取新版本后检查发行文件清单，再重跑 `install.ps1`。重复安装保留原数据库、历史起点、来源范围、本人身份和人工决定。启动时只处理这个安装自己的工作台。

从 alpha.1 升级到 **0.1.0-alpha.2** 时，安装入口会核对安装身份，在个人数据目录的 `backups` 中建立一致数据库备份并输出路径，再启用 V44 增量整理。保留业务数据、原目标、人工决定、历史修订、审计及提醒节点；只迁移检查依据，真实未完成的整理继续保留。已经开启时重复安装不重复迁移。使用 `doctor.ps1` 核对“增量整理”，然后按[日常工作流](daily-workflow.md)执行一次。

已有定期任务还须由当前 Codex 按 [automation.md](automation.md) 更新旧正文并读回，沿用原频率、通知和截止；安装器不会擅自修改任务。可直接交给 Codex：

> 请按 docs/update.md 把现有个人工作助手升级到当前版本，保留数据、配置和本地修改，核对升级备份与增量状态，并更新本项目已有自动化任务的整理规则，保持原有频率、通知和截止，最后验证一轮增量整理。

源码有本机修改时先审查差异并保留，不能用强制覆盖或 `reset --hard` 更新。下载 ZIP 的用户先停止旧工作台，把新代码解压到新目录，将自己的配置复制过去；核对数据目录后启动，新目录不得初始化成另一个“看似成功”的空库。

回滚保留旧代码和对应数据库备份；数据库升级后不能假定旧程序仍然兼容。换设备时只迁移用户选择的个人资料备份与不含密钥的配置，新电脑重新核对微信账号目录、程序版本和飞书登录，不能复制旧进程身份或微信读取密钥。

卸载程序前用 `stop.ps1` 停止本机工作台。删除程序目录不会自动删除个人数据库，也不会取消已经在飞书运行的云端提醒；用户要求停止全部自动运行时，还须在本人的 Codex 和飞书分别停用并读回。
