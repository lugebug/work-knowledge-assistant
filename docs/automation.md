# 定期更新与本人提醒

本项目不复制维护者的自动化任务，也不在安装脚本里写 Codex 的内部任务文件。任务由朋友自己的 Codex 使用其可用的定期任务工具创建和读回。

用户已经要求自动更新时，先完成一次实际采集和业务整理，再集中确认运行时间。可建议工作日9:00至19:00每两小时检查、18:30生成摘要；这是建议，不是既有承诺。按用户选择创建任务，已有对应任务优先更新，避免重复。

可用于任务正文的模板：

> 在这个个人工作助手项目中，先读 AGENTS.md、docs/daily-workflow.md 和 docs/incremental.md，核对本人账号及获准范围。采集新增和修订文字后用 incremental prepare 读取本轮差异，只判断未整理版本、新的人工答复和实际变化；先更新受影响工作，再汇总相关项目。已确认人员、组织、角色及优先级无新依据不复核，内部复核日期和项目一般进展不触发全量重算。用 pending 定向补目标校验、分析、行动承接及必要排序；只有新事实改变排序依据时登记 priority-impact。原目标达成即同步完成和结果，独立后续另外承接，时间归属具体事项。人工答复按身份和修订实际落实，保留原话和决定。提醒已启用时采集前后同步并读回云端，保留真实到期、改时暂停、完成取消及送达回执。实际写回后登记逐版本 finish 回执，再 review-check、settle 和 checkpoint；并发新变化只补差异，不遗漏、不强行跳过。保留来源失败与覆盖缺口，无变化或不可行动时保持安静，仅在有意义变化、完成、失败或需要用户处理时通知。

**已有安装升级：** 先使用 Codex 的自动化工具查找本项目对应任务，读取实际保存的完整配置，再按上方规则更新正文。保持既有任务身份、频率、目标聊天、通知设置、运行位置和截止；摘要任务沿用摘要用途，只把全量重审改为本轮差异与必要提醒。读回确认后再报告“自动更新机制已升级”。不能复制维护者任务、通过写内部任务文件替代工具，或重复创建一组任务。当前没有对应工具时保留明确待办，手动增量流程仍可执行。

创建成功后，将工具实际返回的任务身份、截止或长期运行选择登记到本机状态；不要自行编造任务身份。若 Codex 当前没有相应能力，明确留下“定期任务未建立”，手动执行工作流仍可用。

用 `.venv\Scripts\python.exe -X utf8 app\bootstrap.py record-schedule --automation-id 实际任务身份 --description '本人已选的运行安排'` 登记。多项任务重复传入 `--automation-id`；有截止则传入含时区的 `--until`，长期运行省略。入口核对本机实际任务文件和启用状态，仅读取 Codex 配置，再更新本安装的显示及采集截止。工具显示成功但本机尚未同步文件时，先等待同步再核对，不写伪造任务文件。之后运行 `app/raw_manage.py status` 读回定期状态。

本机任务需要电脑开机、网络可用且 Codex 能访问项目；本机任务的这一条件由[官方说明](https://learn.chatgpt.com/docs/automations?surface=app)确认。安装本项目不会让关机的电脑继续读微信或更新业务库。

用户另行要求飞书提醒后，`app/reminders.py` 提供共用设置、计划、暂停／改时、云端绑定及同步入口。先读取帮助和当前设置，核实本人档案已关联正确飞书账号，然后按本人选择配置。提醒到期发送不代表工作完成；工作结束、取消或用户暂停须同步停止对应节点。

关机后仍需提醒时，需在本人的飞书建立并验证云端工作流。现有程序可同步队列，但新租户的应用权限、表格、工作流和实际送达仍需首次设置和验证。未验证前，不声称此能力已在该用户处上线。
