# 第一次安装和接入

本流程由朋友自己的 Codex 执行。以真实读回结果推进，已经完成的步骤直接复用，不重复要求登录或覆盖个人选择。

## 1. 准备个人库

集中确认本人称呼、当前工作单位或业务范围、希望归档的起始日期。首版只归档文字及微信已有的语音转写，不下载图片、文件、音视频。

在当前目录运行 `install.ps1 -Name 本人称呼 -Since 起始日期`。已装好则先运行 `doctor.ps1`，不要重建数据库。安装缺少依赖时根据明确错误补齐，不能跳过失败宣称装好。若 Windows 执行策略禁止脚本，应说明实际限制并由用户按本机管理要求处理；不要擅自降低策略。

运行 `.venv\Scripts\python.exe -X utf8 app\bootstrap.py paths` 读取本安装路径。所有资料、输入和报告放个人数据目录，不能写进仓库。CLI 也可通过 `WORK_KNOWLEDGE_CONFIG` 指定独立配置；测试必须用独立配置和目录。

## 2. 飞书：本人登录，再确认读取范围

使用本项目 `.tools\node_modules\@larksuite\cli\scripts\run.js`，用 Node.js 运行。先 `auth status`；已登录正确身份就复用。没有配置时按官方 CLI 当前帮助运行 `config init --new --brand feishu --lang zh`，把实际生成的登录链接交给本人操作。本人已有 CLI 配置时不擅自换应用。

只申请本轮读取需要的权限。基本范围为聊天、文档、云盘、知识库、妙记文字和任务的读取；具体名称以本安装 CLI 的命令帮助和权限检查为准。权限不足时只补缺失项，不为采集申请发消息、删除或修改文档的权限。使用 `auth login --scope ... --no-wait --json` 可生成链接，随后用实际返回的设备码完成登录；设备码和令牌不写进 Git。

运行 `app/bootstrap.py feishu-status`，将核实的本人名称显示给用户，确认这是要接入的账号。再确认其全部可见飞书内容是否均为工作资料：

- 全部属于工作：本人确认后运行 `app/bootstrap.py bind-feishu --confirm-owner --all-visible-work`。
- 只选部分：运行 `app/bootstrap.py bind-feishu --confirm-owner`，后续只登记明确选择的聊天或文档，不运行全范围自动发现。

身份绑定只记录本人账号和授权范围，不读取聊天正文。切换成别的账号会停止采集；不同人应使用独立个人库。

## 3. 微信：核对版本、账号和工作来源

先运行 `app/bootstrap.py discover-local`；仅检测程序、版本和常见数据目录，不读联系人或聊天。自定义目录可增加 `--root`。存在多个账号时由本人选择，不能自动合并。版本未适配时保留清楚的未接入状态，可先用飞书和用户提供的文字继续工作。

本人确认只读接入后运行：

```powershell
.venv\Scripts\python.exe -X utf8 app\bootstrap.py bind-wechat --database-dir '本人账号的db_storage目录' --executable '微信程序路径' --account '已核实的本人账号身份' --confirm-owner
```

本人允许查看联系人／群目录后，再运行 `app/wechat_directory.py --confirm-directory`。输出仅含身份、备注、昵称、群标记和本机记录时间，不含聊天内容。清单保存到个人数据目录，默认不在终端输出全部私人目录。Codex 只用这些元数据帮助用户确认工作来源，界面叙述用备注或昵称，不给用户展示原生ID。

先按当前工作关系和群用途确认一批来源。明确的可按用户已给的范围登记；不确定的集中列出有意义的候选，不能因为同事在群里就判为工作群。生活群和明确排除的来源持续排除。

将确认结果写为个人数据目录下的新 JSON 数组，交给 `app/raw_manage.py register-work-chats --input 文件`。每项包含平台、准确身份、显示名称、本人确认依据及带时区的起点。格式见 `docs/connectors.md`。此步骤只登记，下一步才取正文。

## 4. 首次采集、整理和读回

先选择1至3个本人确认的工作来源，运行明确来源的 `raw_manage.py sync --source ...`，核对对象和时间范围，再按 `docs/daily-workflow.md` 完成一轮整理。确认工作台显示的是本人的资料，已有工作能更新，未知结果没有被猜为完成。然后再扩大到全部已批准来源。

飞书全范围自动发现只有第二步明确批准后才运行；微信始终按已确认名单读取。零条消息、本机缺历史、权限失败、已采集待整理分别报告。

## 5. 定期更新和提醒

用户已要求定期更新时，按 `docs/automation.md` 建立本人的定期任务，并读回任务身份、频率和目标目录。若工具不可用，明确记录未建立，不写一个本地配置就声称已启动。电脑关机期间本机读取和 Codex 整理不运行。

提醒按本人选择单独设置；未要求提醒时不发测试消息、不创建云端表格。已要求提醒时，先用共用入口生成具体计划，在本人的飞书完成通道设置和实际送达验证。云端流程只执行最后成功同步的计划，关机时不会产生新分析。

收尾报告四个结果：系统是否启动、哪些账号已接入及覆盖到何时、哪些资料已实际整理、定期更新／提醒是否真实启用。把尚未完成的接入步骤留在个人数据目录，重开 Codex 时接着做。
