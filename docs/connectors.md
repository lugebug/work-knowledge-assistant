# 微信和飞书接入

## 支持范围

| 来源 | 首版接法 | 本人要完成的步骤 | 验证边界 |
|---|---|---|---|
| 微信 | Windows 本机只读适配 | 登录自己的微信、确认账号及工作会话 | 4.1.15.55；只读本机已有历史；其他版本待适配 |
| 飞书 | 官方 CLI 1.0.94 | 完成登录及可读权限，确认工作范围 | 账号与应用身份每次读取前核对；没有权限的内容保留缺口 |
| 自己提供的资料 | 文字归档入口 | 明确交给助手的文字 | 逐字留存、保留修订，不冒充远端采集 |

第三方依赖安装在项目的独立环境内，账号授权由飞书官方 CLI 自己保存。本项目配置不保存飞书令牌或微信密钥。微信只读适配只调用查询进程及读取内存的接口，查询页在内存解密，拒绝源文件写入；它不是官方微信开放接口，不承诺未来版本兼容。

## 登记已确认的工作会话

下面是虚构示例。替换为本人实际选择的身份、日期和原话，存到个人数据目录：

```json
[
  {
    "platform": "wechat",
    "identity": "work_group_example",
    "name": "示例项目工作群",
    "basis": {
      "note": "本人明确确认这是当前项目工作群",
      "evidence": ["本人首次接入时对该群的确认原话"]
    },
    "since": "2026-10-01T00:00:00+08:00"
  }
]
```

```powershell
.venv\Scripts\python.exe -X utf8 app\raw_manage.py register-work-chats --input 本人确认的清单.json
.venv\Scripts\python.exe -X utf8 app\raw_manage.py status
```

先读回名单，再采集明确来源。暂停、拒绝或候选状态不能被批量登记重开；用户改变选择时用已有来源的修订入口留下审计。

## 接入失败怎么处理

缺依赖可重跑安装；未登录重新完成本人授权；权限不足按官方 CLI 返回补需要的读取范围；账号发生变化先核对本人身份。微信不在支持版本时不要自动降级微信、替换程序、复用旧进程或扫描其他账号。保留失败原因和上次成功位置，其他已接入来源可以继续。

飞书或微信的“目录可见”不等于“正文已取到”，采集成功也不等于工作语义已整理。每次报告分开列明这些状态。

## 数据流

来源文字 → 本人电脑上的原文版本 → Codex 核对事实与工作 → 本人电脑上的工作库 → 浏览器工作台。

Codex 会按其账户设置处理交给它的工作文字。GitHub 和发行包只存程序；个人数据库、目录清单和输入文件不加入仓库。提醒启用后，会把用户选择的提醒内容同步到用户自己的飞书。

官方参考：[飞书 CLI 安装与授权](https://github.com/larksuite/cli)、[APSW 只读 VFS 接口](https://rogerbinns.github.io/apsw/vfs.html)。
